# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 0.1.x | Yes |

## Reporting a Vulnerability

Please report vulnerabilities responsibly:

1. Do not open a public GitHub issue for security vulnerabilities.
2. Email the maintainer directly or use [GitHub private vulnerability reporting](https://github.com/Lucenx9/forktty/security/advisories/new).
3. Include a description, reproduction steps, impact, affected version/commit, and any suggested fix.

We aim to acknowledge reports within 48 hours and provide a fix within 7 days for critical issues when feasible.

## Security Model

ForkTTY is a Linux-only local desktop application. Its primary trust boundary is the current user account.

Assumptions:

- The user running ForkTTY is trusted.
- The local user account and filesystem are not already compromised.
- Same-user local processes may be able to interact with user-owned runtime resources.
- User-authored hooks and notification commands execute with the user's privileges.

ForkTTY does not make external network calls and does not treat the local Unix socket as a remote security boundary.

## Security Boundaries

| Component | Current protection |
| --------- | ------------------ |
| Unix socket | Defaults to `$XDG_RUNTIME_DIR/forktty.sock`; parent directory is created private when needed and validated for owner-only access on the default path; socket permissions are owner-only; request lines are capped at 1 MiB. |
| PTY spawn | Configured shell must be an absolute path to an executable regular file. Spawn cwd is resolved to a usable directory, with AppImage mount cwd fallback handling. |
| ForkTTY config | `~/.config/forktty/config.toml` must be a regular file and no larger than 1 MiB before parsing. Saved config validates shell, font size, sidebar position, worktree layout, and notification command. |
| Notification command | Empty disables it. If set, it is parsed with `shell_words`; the first token must be an absolute executable file; remaining tokens are passed as argv; no `sh -c`; title/body are passed through environment variables. |
| Desktop notifications | Sent through `notify-rust` / XDG D-Bus. The configured notification title/body may contain terminal output generated by local shells or agents. |
| Worktree names | Rejects empty names, `/`, `\`, `..`, and NUL. |
| Worktree paths | Canonicalized and verified against Git repository boundaries before sensitive operations. |
| Worktree hooks | Only `.forktty/setup` and `.forktty/teardown` are executed; hook paths are canonicalized and must remain inside the worktree; execution uses argv, not `sh -c`. |
| Socket `cwd` for worktree methods | Caller-supplied cwd must be in the same Git common directory as an already-open frontend workspace. Subdirectories and linked worktrees in that repository are accepted; unrelated repositories are rejected. |
| AppImage packaging | Root desktop/icon symlinks are normalized; unsafe icon names containing `/` or `..` are ignored; packaging refuses absolute root symlinks. |
| Ghostty theme parser | Theme names are allowlisted to prevent path traversal. |
| WebView | CSP restricts the app to local content and avoids remote scripts. |
| Logs | Newlines are sanitized before writing structured log lines. |

## Notification Command Details

`notification_command` currently supports static argv arguments:

```toml
[general]
notification_command = "/usr/bin/notify-send --app-name ForkTTY"
```

ForkTTY executes the first token directly. It does not invoke a shell, so shell features such as pipes, redirects, `&&`, command substitution, globbing, and environment variable expansion are not interpreted.

The payload is provided through:

- `FORKTTY_NOTIFICATION_TITLE`
- `FORKTTY_NOTIFICATION_BODY`

Do not point `notification_command` at a script unless you trust that script with local terminal output. A stricter no-extra-arguments policy is a backlog hardening item, not current behavior.

## Config Hardening

The ForkTTY TOML config loader opens the file, verifies it is a regular file, rejects files over 1 MiB, and reads through a bounded reader before parsing.

This bound applies to ForkTTY's own config file. Ghostty compatibility parsing is a separate path for the user's local Ghostty config and theme files.

## Residual Risks

- Same-user local processes remain inside the local trust model and may interact with user-owned files or sockets.
- Terminal output can include sensitive text. If desktop notifications or `notification_command` are enabled, notification title/body may expose that text to the desktop notification service or custom executable.
- User-created `.forktty/setup` and `.forktty/teardown` hooks are executable local automation and run with the user's privileges.
- Worktree operations modify local Git checkouts and branches; users should review changes before merging or removing worktrees.
- Session files and logs can contain local paths and workspace names.

## Dependencies and CI

- Rust dependencies are audited with `cargo audit` in CI.
- npm dependencies are audited with `npm audit` in CI.
- CodeQL runs in CI.
- Dependabot is configured for repository dependency updates.

Security automation reduces risk but does not replace manual review of privileged local execution paths.
