
## 2024-05-18 - Avoid Cloning Large Structs From The Model
**Learning:** In the `WorkspaceModel` (crates/forktty-core/src/model.rs), retrieving a surface via `self.surfaces.get(surface_id)?.clone()` causes a huge eager clone of the entire `Surface` struct. The `Surface` struct is large because it contains a `persisted_scrollback` buffer which can be up to 64KB (`Option<String>`). Functions like `split_with`, `add_tab`, `prepare_root_surface_replacement`, and `close_surface_with_replacement` were unnecessarily eager-cloning the entire surface just to extract fields like `workspace_id` or `cwd` before performing basic validation checks (such as ensuring the workspace still contains the surface leaf or checking for a sole root tab).
**Action:** When accessing a large struct like `Surface` from the map to retrieve specific properties, use a block to map over the borrowed value and clone only the necessary individual fields (e.g., `let (workspace_id, cwd) = { let s = self.surfaces.get(id)?; (s.workspace_id.clone(), s.cwd.clone()) };`). This avoids the expensive full clone of the entire struct (specifically avoiding the clone of the 64KB scrollback buffer), and early-returns on validation failure no longer trigger unnecessary allocations.
